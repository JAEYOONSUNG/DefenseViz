# DefenseViz v2 interface contract

Python >=3.10 installable package and CLI, offline by default. Product DefenseViz; evidence policy DNMB. Preserve original repositories; use existing policy and registry logic with pinned source provenance. Generic tables, arbitrary sample identifiers/counts and novel families, no manuscript identities in production code. No claim of activity or independent predictive performance. This document describes the retained normalized-project API. The additive DNMBsuite input, saved-evidence aggregation and full publication figures are specified in [SUITE_CONTRACT.md](SUITE_CONTRACT.md).

## Canonical in-memory data (JSON-serializable dictionaries)
- samples: list of {sample_id: nonempty str, label: str, genus: str optional, species: str optional, highlight: bool optional}. IDs unique, order preserved; arbitrary Unicode labels.
- calls: list of {sample_id, gene_id, caller, family, category, system_id: str or null, role: str or null, rm_type: str or null, evidence_kind: 'final_member'|'hmm_hit'|'reference_hit', source: str optional}. Canonical category values: R-M, Modification, Nuclease, CRISPR-Cas, Abortive infection, Other mechanisms, Unresolved. Unknown family kept, category Unresolved unless an explicit mapping supplies category. Final members are not raw HMM hits. Native system identity scoped by sample/caller/system_id. A gene may have multiple family calls; preserve that, do not sum overlapping rows as union. R/M/S/RM/C/Aux roles distinguished, no new biological role from mere text keywords.
- evidence_records: list of {sample_id, gene_id, evidence: full DNMB Evidence dictionary, provenance: dict optional}. Complete policy evidence is needed for scoring; absent evidence is unassessed. Duplicate sample/gene records are errors; no identifier concatenation or splitting. For native DNMB feature exports an explicit adapter may construct typed evidence using available fields, but must not fabricate scientific support.
- genes: optional list {sample_id,gene_id,contig,start,end,strand,sequence_sha256}. Coordinates 1-based inclusive, start<=end, strand '+'/'-'. Context computation uses exact compatible family/role plus bounded geometry, not mere adjacency of arbitrary calls. Missing coordinates cannot supply context.
- coverage: list {sample_id,caller,status: 'complete'|'missing'|'not_run'}. Only complete coverage allows displayed zero; others display NA. Every call must belong to complete coverage or validation rejects conflict. An explicit empty file marked complete represents a true zero saved-call result, not biological absence.

## Public Python interfaces
`defenseviz.io.load_project(config_path: Path) -> dict` returns {samples,calls,evidence_records,genes,coverage,inputs,options}. inputs=list of resolved Path objects actually read. options mapping includes policy?, title?, max_rows_per_page?, max_families_per_page? and is kept separate from analysis. All file references resolve relative to config, never CWD. Exceptions ValueError with actionable context; no silent bad-row skipping. No network. `.xlsx` import optional via openpyxl; core fixture TSV/JSON works without it.
`defenseviz.analysis.integrate(samples,calls,evidence_records,*,coverage=None,genes=None,policy=None) -> dict` returns at least:
  samples (original order), callers (stable unique), families list {family,category}, cells list {sample_id,family,category,cds_count:int,system_count:int,caller_counts:dict}, sample_summary list {sample_id,union_cds,rm_pool_cds,scored_cds,retained_cds,unassessed_cds,caller_counts:dict}, decisions list {sample_id,gene_id,status:'scored'|'unassessed'|'out_of_scope',evidence?,decision?}, overlap list {sample_id,callers:list,gene_ids:list,count:int}, rm_components list {sample_id,rm_type,role,count:int,supported_count:int}, native_system_counts list {sample_id,caller,family,count:int}, policy dict parameters, warnings list strings, coverage. Cells counts distinct genes; system_count must be sum of explicitly caller-specific native systems, labeled as such, never de-duplicated biological systems. HMM-only and reference-only detections separately preserved in `evidence_calls`; not native member counts. Explicit record lists empty when no data.
`defenseviz.plot.render(result: dict, output_dir: Path, *, title='DefenseViz', max_rows_per_page=40, max_families_per_page=24) -> list[Path]` generates `figure2_ab.pdf`, `figure2_ab.svg` (single page) or numbered SVG pages, plus layout JSON with actual page/panel/row/column bounds. Live SVG text. Dynamic pagination so labels and cells do not overlap. Panel a describes actual policy and available evidence, not unsupported methods. Panel b includes caller count bars, R-M evidence/retention, type/subunit counts, family/category matrix, sample metadata/highlight. No need to reproduce cohort-specific publication layout literally. Every data length proportional to values, fixed bar thickness; highlight pink.

## Config format version 1
JSON object {schema_version:1,samples:'samples.tsv',calls:[{format:'normalized'|'defensefinder'|'padloc'|'defensepredictor',path:'calls.tsv',sample_id?:'one_sample',caller?:'label',id_map?:'mapping.tsv'}],evidence?:'evidence.json',genes?:'genes.tsv',coverage?:'coverage.tsv',family_map?:'families.tsv',options?:{}}.
Normalized calls require sample_id,gene_id,caller,family; optional columns as above. Adapters document exact accepted native exports and explicit alias mappings. Every source requires sample binding from row or config. All input joins use explicit sample/gene keys; native ID maps must be one-to-one within sample. Never silently equate protein IDs and locus tags. Required caller coverage is inferred complete only for explicitly supplied per-sample source files; multi-sample files without coverage cannot infer omitted sample completion.

## CLI (root owned)
`defenseviz validate config.json`; `defenseviz run config.json --out output`; `defenseviz demo --out output`; `defenseviz version`. Run performs load/strict validation/integration/render/table exports/provenance in a fresh output directory and reports stages as saved-call evaluation + rendering. No destructive overwrite; atomic staging then publish on success. Receipt includes all input/code/config hashes, exact command, versions, exit/time, policy hash and stage kinds. The assess subcommand evaluates supplied registry candidates independently; evidence_extension feeds source-bound family admission into the same policy run.
